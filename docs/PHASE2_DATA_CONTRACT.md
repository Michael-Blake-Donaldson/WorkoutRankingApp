# Phase 2 data contract

Profile records are owned by the authenticated account. One monotonically increasing version covers preferences, equipment and measurements; every successful mutation appends a private profile/equipment snapshot and idempotency receipt. Program generation is still a later-phase workflow and cannot be triggered by a profile edit.

New relational tables: fitness_profiles, body_measurements, equipment_profiles, equipment_items, profile_revisions and profile_mutations. They use foreign keys, per-owner indexes, forced row-level security and explicit runtime grants. Server transactions set the authenticated owner as a transaction-local setting. Runtime cannot edit or delete measurement/revision history. A single active default equipment location is enforced by partial unique index; child equipment and correction references enforce matching ownership.

Measurements store decimal SI: kg for weight, metres for height/circumferences, six decimal places. UI unit changes never rewrite measured values. Conversion factors: 1 lb = 0.45359237 kg; 1 in = 0.0254 m. Corrections append a new record linked to an existing current record of the same owner and metric, with a reason. BMI uses weight/height², rounded to one decimal, choosing the latest valid height at or before that weight's recorded instant. No categories, body composition inference or ranking contribution are attached.

Reversible implementation assumptions: onboarding requires profile basics, one equipment location (including an explicit no-equipment location), height and weight; no DOB or age is collected yet. Training availability is weekdays plus session minutes, not a generated calendar. Likes/dislikes and limitations are private text until Phase 3 introduces reviewed taxonomy. Optional nutrition targets are entered manually; no meal logger or automatic target recommendation is implemented. Sound/haptic permission preferences prepare future workout alerts; no permission prompt or alert is claimed.

Data-entry bounds are validation limits, not medical recommendations: session duration 10–240 minutes, weight 0.1–1000 kg, height 0.2–3 m, other lengths 0.01–5 m, configured equipment loads above zero through 2000 kg, optional calories above zero through 20000 and optional protein grams above zero through 1000. Timestamps are UTC instants; the profile stores an explicit validated IANA timezone. Recorded times cannot exceed the present by more than five minutes. Defaults must be reviewed in onboarding.

Sharing is off by default. The only permission available is competition summary consent for future competition. It never grants access to measurements, nutrition targets, pain/limitations or notes. No opponent health-data endpoint is added. Private responses and pages remain outside service-worker caches.
