# Acceptance tests and initial testing strategy

Status: planned application tests; none of the production behaviors below have been implemented or executed. The only executable Phase 0 check is `scripts/check-phase0.ps1`, which checks required documentation, local links and key section coverage. It cannot certify correctness of prose or runtime features.

## Test layers

Phase 1 establishes TypeScript strict checking, lint, Vitest unit tests, real disposable PostgreSQL integration tests and Playwright browser flows, with accessibility checks. Exact commands/package manager are defined with the actual manifest; no invented runnable npm commands here. CI should run clean install, static checks, pure rules, clean migrations, integration and browser smoke flows. Release expands to real iPhone/manual accessibility, performance and backup restore evidence.

Inject clock, timezone, IDs and immutable rules into pure calculations. Test golden expectations independently of implementation, boundary/property invariants, transaction races and authorization failures. Use real persistence for auth, idempotency, revision and completion tests. Mock only external email/push delivery boundaries, clearly labeled; do not mock a database or calculation to claim production completion. Each test records rules version and phase, with fixtures free of actual health data/secrets.
